## Whole-system posture

Arda is a local-first, single-operator personal-agent ecosystem and distributed
digital organism. One Rust composition root coordinates governed Workbench
execution, Manwë placement/routing, standard A2A node exchange, Varda evidence,
Vairë continuity and learning, homeostasis/recovery, read-only Arandur
orchestration, native launcher packaging, and backend-owned HUD projections.

The workspace currently resolves 19 Cargo packages. `core/projects/tasks/queue.jsonl`
is the canonical queue ledger; `core/state/queue_active.json` and
`core/state/queue_summary.json` are generated read projections, not parallel
authorities. Read `queue_active.json` first for task selection.

## Digital-organism program closeout

The 2026-08-21 through 2026-08-25 Digital Organism Program completed all eight
stages and is retained as a historical program under
[`docs/archive/digital-organism/`](docs/archive/digital-organism/README.md). Its
[`closeout synopsis`](docs/archive/digital-organism/SYNOPSIS.md) records the
organism contracts, A2A mesh, adaptive placement, memory/learning, homeostasis,
Arandur cycle, operator-accepted living-mesh proof, and read-only hardware
portability proof.

This closeout does not prove repeated daily usefulness. Open evidence boundaries
are repeated-use evidence for the living mesh, a stronger-GPU transfer
demonstration, and any embodiment beyond read-only projection.

## Active completion program

The [`Arda Whole-System Completion Program`](docs/plans/ARDA_WHOLE_SYSTEM_COMPLETION_PROGRAM.md)
is now active. The prior Core Arda Usefulness Repair plan was rejected because it
reduced the operator's intended system to a short conversational acceptance
journey. Those interactions remain useful surface tests, but they are not the
definition of Core Arda.

The actual gate is a canonical autonomous loop that can retrieve context, define
an outcome, decompose it across real connected projects, schedule and place work
on suitable local/cloud capability, execute, verify, independently review where
needed, revise or retry failed work, resume across restart, and close only when
acceptance criteria pass. A daily research and project-audit cycle must feed that
same loop and produce verified improvements rather than disconnected reports.

The [`Ambient Agent Program`](docs/plans/ambient-agent/README.md) therefore
remains on hold. Mirromere, expanded RELIC embodiment, sensors, physical outposts,
external agent accounts, funded action, and commercialization are not authorized
by the digital-organism closeout.

## Release posture

Version `0.9.0` is self-qualified and unsigned. Independent flow review is
intentionally omitted for this personal baseline and is not claimed. It is fit
for operator use and disclosed alpha feedback, not public-production or final
`1.0.0` qualification.

A future final release remains fail-closed on exact signed bytes, supported
lifecycle qualification, independent release-critical security/code review,
genuine operator evidence, and the required whole-system proofs.
