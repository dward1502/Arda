# P2.4 live phone acceptance evidence

Date: 2026-08-09

## Scope and evidence boundary

This receipt covers one authenticated Discord conversation routed through the
Hermes Gateway into Arda's loopback-only operator endpoint. Hermes retained the
Discord credential and allowlist decision. Arda received only the normalized,
credential-free event projection. Operator and conversation identifiers remain
in the owner-local durable ledger and are intentionally omitted here.

The operator reported the platform-visible approval and cancellation replies.
The local evidence below independently verifies the resulting canonical Arda
records, active-provider cancellation path, restart recovery, and replay
rejection. No synthetic callback invocation is treated as live transport proof.

## Live acceptance receipt

| Requirement | Evidence |
| --- | --- |
| Configured transport | `arda-operator-bridge` version `0.1.0` was enabled in the Hermes Gateway; `arda.service` and `hermes-gateway.service` were active. The Arda ingress remained bound to loopback at `POST http://127.0.0.1:7878/v1/operator/messages`. |
| Authenticated conversation | Hermes authorized and normalized the Discord events before forwarding. The durable Oromë records carry `authenticated=true`, `authentication_method=gateway_identity`, and matching operator/event identity; the operator ID is omitted from this repository receipt. |
| Capture | Platform event `1535935687361175572` became Oromë operation `capture` and canonical personal capture `4648e678-9534-5c2d-bb5b-6fdd44884cd7`. The group-channel operator projection retained `text=null`; the owning personal inbox retained the exact capture content. |
| Approval | Platform event `1535994587649282098` became Oromë operation `approve`. Its scoped approval was consumed once, and run `p24-live-cancel` node `approval` advanced `pending -> ready -> running -> succeeded`. Receipt `gateway:1535994587649282098` was propagated into the dependent execute node. |
| Live cancellation | Platform event `1536000797886910474` became Oromë operation `cancel`. The provider request returned `run 'p24-live-cancel' was cancelled while provider execution was active`, not a natural timeout. The matching Hermes child was absent after return. The run journal records execute-node `cancelled` plus cancellation reason `P2.4 authenticated live-child cancellation proof`; the operator reported the correlated Discord reply `Cancelled run p24-live-cancel`. The exact cancelled child PID was not retained, so this receipt relies on the active-provider request outcome, post-cancel process absence, durable journal, and the adapter reaping test rather than claiming PID-level evidence. |
| Restart recovery | Arda and Hermes Gateway were restarted after cancellation. Both returned `active`, Arda health returned `ok`, the Oromë ledger retained exactly three accepted live events, and the run recovered as `approval=succeeded, execute=cancelled`. |
| Replay rejection | Reposting the exact normalized cancellation event after restart returned HTTP `409` with `duplicate transport event: 1536000797886910474`. The durable Oromë ledger remained at three events and no second cancellation transition was appended. |
| Correlation | Platform event IDs appear in Oromë `incoming.event_id`, evidence refs, approval consumption, run idempotency keys, and `gateway:<event-id>` durable receipts. Sensitive message text and platform credentials are absent from the group operator projection. |

## Honest limitations

- This receipt proves capture, scoped approval, active-child cancellation,
  restart-safe recovery, replay rejection, and response correlation for the
  required P2.4 path. It does not claim all broader P2.3 phone commands are
  implemented.
- The operator-visible Discord response is direct human-observed evidence. Arda's
  current operator-session projection still records delivery state as `pending`;
  this receipt does not reinterpret that field as a transport acknowledgement.
- Credentials, raw Discord objects, operator identity, and conversation identity
  are not copied into this repository evidence file.
