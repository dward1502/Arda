How Arda Operates

governed action, not free-running automation
← atlas index

INTENT → VERIFIED OUTCOME → GOVERNED LEARNING

Intent / condition

Operator request or observed condition enters with identity and scope.

Retrieve context

Tasks, memory, evidence, project lineage, freshness, and uncertainty.

Classify needs

Required and optional capabilities; sensitivity and egress limits.

Assess impact

Governance, Love Dynamics, JouleWork, reversibility, authority class.

Compose workers

Smallest capable set of deterministic tools, Hermes, hosted or local models.

Approve / bound

Ask only when required; otherwise perform a reversible allowlisted action.

Execute + recover

Restart-safe run graph with cancellation, replay protection, or compensation.

Verify + receipt

Acceptance evidence, durable semantic receipt, operator update, next state.

Reflect without self-authorizing

Learn from outcomes, preserve uncertainty, and propose changes. Learning never silently expands authority.

TRUTHUnknown, stale, partial, degraded, unavailable, and failed are valid states.
LANGUAGEFact, inference, suggestion, approval, and action remain visibly distinct.
RECOVERYConsequential mutation is observable exactly once or has explicit compensation.

ACTION AUTHORITY LADDER

OBSERVERead state; receipt if persisted.
ORGANIZEClassify, prepare, rank; disclose inference.
INFORMCalm status/reminder under timing and fatigue policy.
PROPOSEPlan, patch, draft; no external side effect.
EXECUTE ↶Allowlisted and reversible; gated and receipted.
CONSEQUENTIALMessage, deploy, payment, retention: explicit scoped approval.
PROHIBITEDCovert surveillance, diagnosis, silent authority expansion: fail closed.
Council votes and model confidence never lower the required authority class.
