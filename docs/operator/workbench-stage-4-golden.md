# Workbench Stage 4 golden-path reproduction

This guide reproduces the bounded Rust, Python, and restart proofs without changing the Arda workspace or requiring external model credentials. The fixtures are copied into temporary directories, initialized as clean Git repositories, mutated only after an approval receipt is recorded, tested, reviewed, closed, and deleted when each test exits.

## Prerequisites

- Git
- a Rust toolchain that can build the workspace
- Python 3.11 or newer
- the repository checkout

No Python fixture is added to the Cargo workspace. No network access, secrets, external model provider, or HUD process is required by this deterministic proof.

## Reproduce from a fresh checkout

```bash
git clone <arda-repository-url> Arda
cd Arda
scripts/workbench/run-stage-4-golden.sh /tmp/arda-stage-4-evidence
```

The command exits nonzero on any failed attach, contract validation, approval chain, mutation, declared test, review/close projection, restart, duplicate-mutation assertion, or evidence decode. A successful run prints these three run IDs:

- `golden-rust-run`
- `golden-python-run`
- `golden-boundary-recovery`

Omit the output argument to refresh the checked-in evidence under `docs/evidence/workbench-stage-4/`.

## What each proof does

### Rust repository

`workbench_rust_golden` copies the Rust fixture, creates a clean Git commit, validates `arda-project.json`, records objective/plan/approval state, and executes the bounded two-line greeting and expectation change through the Hermes adapter contract. The deterministic Hermes fixture fails once before mutation, retries automatically, exports tool and test evidence, then completes verify, review, close, result, and project-memory projection.

The adapter route is deliberately identified as `fixture-provider/fixture-model`; it is a deterministic adapter-contract route, not a claim that a paid model provider was contacted. Its normalized fixture cost is recorded in the result. Production Hermes provider routing remains independently replaceable behind the same receipt contract.

### Python repository

`workbench_python_golden` copies the Python fixture to a temporary path outside the Arda Cargo workspace and imports only the versioned Python adapter SDK through `PYTHONPATH`. The JSONL process receives an invalid bounded request first and proves failure before mutation, then resumes with a recovery token, performs the approved source/test update, runs the declared `unittest` command, and closes the graph. The route has no model/provider and therefore records zero model cost.

### Crash, restart, and duplicate mutation

`workbench_boundary_recovery` launches a real child test process and terminates it with exit code 86 after each durable boundary: planned, plan, approval, execute, verify, review, close, and result. It also terminates after the mutation but before the execute receipt. On restart, the uncertain execute is replayed against an idempotent target-state mutation. The proof requires two mutation attempts, exactly one observable repository mutation, one final diff occurrence, and no extra journal event on a post-close replay.

## Security review of the golden path

- All repositories and state roots are isolated under test-owned temporary directories.
- Project contracts require canonical relative paths, declared commands/checks, denied network access, explicit write authority, and environment-variable names rather than values.
- The JSONL adapter starts an absolute executable in a canonical project-root-contained cwd, clears inherited environment, restores only an explicit allowlist, bounds line size and timeout, and checks advertised capabilities.
- The Python mutation handler accepts one exact approved argument shape and touches two fixed fixture paths. It does not accept a browser shell string or an arbitrary path.
- The deterministic Hermes fixture and Python adapter are test fixtures only; neither is installed as a production executable.
- No fixture reads credentials, opens the network, pushes, merges, deploys, or writes outside its temporary project/state roots.
- The restart proof covers the uncertain mutation/receipt gap and fails unless observable state is exact-once.

No critical or high-severity issue was identified in this bounded golden path. Remaining private-beta limitations are explicit: this proof does not validate repository prompt-injection defenses for arbitrary untrusted content, a live paid-model route, autonomous rollback of a non-idempotent third-party tool, packaging, or an invited external evaluator. Those are not silently represented by the deterministic fixture evidence.
