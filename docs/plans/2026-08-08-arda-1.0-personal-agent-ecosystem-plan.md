## Goal

Ship an Arda 1.0 base in which one authenticated operator can use phone and
desktop interfaces to capture personal or project intent; preserve and resume
context; compose Hermes, local inference, council, tools, and optional adapters
according to task requirements; receive bounded proactive assistance; approve
consequential actions; and inspect restart-safe evidence without parallel
queues, memories, policies, or false completion.

## Non-goals

The base release does not require every optional capability to be installed or
operator-accepted:

- production wallet or x402 settlement;
- a specific CRM or Company Operations deployment;
- a Wi-Fi blood-pressure monitor;
- Mirromere hardware;
- ambient always-listening voice;
- camera sensing;
- Home Assistant;
- RELIC/CITADEL write authority;
- universal routing of all Hermes traffic through Manwë.

The 1.0 kernel must define safe attachment points and at least fixture-level
contracts for optional capabilities selected for implementation. Absence of an
optional capability must produce `unavailable` or `not_configured`, not degrade
core operation.

## Global invariants

1. `src/main.rs` plus canonical runtime composition remain the root process
   authority.
2. `arda-core` owns cross-subsystem contracts; `arda-engine` owns durable
   project/run execution.
3. Hermes is a bounded worker runtime; Arda owns project, task, run, approval,
   artifact, and recovery truth.
4. Vairë is the sole canonical long-term memory authority.
5. Oromë owns communications semantics; phone/chat platforms are transports.
6. Manwë is a task-selected model-routing capability, not a mandatory hop for
   incompatible Hermes tool traffic.
7. Council discussion and model confidence never become operator approval.
8. The legacy Love Equation value proxy is not represented as canonical Love
   Dynamics.
9. JouleWork estimates disclose source and confidence; fallback data cannot
   silently authorize consequential work.
10. Human-facing language is a governed effect.
11. Health, payment, external messaging, retention, and production writes use
    explicit scoped authority.
12. Every persisted mutation is exact-once observable, idempotent, or has a
    tested compensation path.
13. Optional capabilities can be disabled or removed without corrupting base
    state.
14. No unit test, generated state file, component export, agent self-report, or
    historical evidence is described as current operator acceptance.

## Dependency spine

```text
P0 doctrine and truth lock
  -> P1 capability-composition contract
     -> P2 phone operator session
     -> P3 multi-worker orchestration
        -> P4 council and local inference
     -> P5 personal continuity and proactive assistance
     -> P6 external adapter and assimilation pipeline
        -> P7 optional economic capability
        -> P8 optional validated-device capability
  -> P9 unified projections and HUD acceptance

```

P2, P3, P5, and P6 may progress in parallel after P1 if they do not modify the
same contracts. P7 and P8 stay behind optional feature and security gates.
P10 cannot close before the required vertical proofs pass.

### P6.3 Build the assimilation state machine

**Implementation evidence — 2026-08-09**

  transition legality, and the evidence required at each maturity boundary.
- Consequential dependency, data, network, or architecture changes cannot enter

  adapter-retained, rollback/removal, and idempotent discovery paths fail closed.

### P6.4 Nightly evaluation routine

The routine may autonomously:

- refresh approved source evidence;
- compare known candidates with measured capability gaps;
- run isolated read-only fixtures;
- generate reports and bounded patches;
- execute tests;
- prepare an adoption proposal.

It may not autonomously:

- scrape and merge arbitrary code;
- bypass licenses or attribution;
- add broad network or secret access;
- mutate private personal data;
- promote every observation into a task;
- install dependencies or change architecture beyond its configured authority;
- merge a consequential patch without its gate.

The same assimilation fixture proves the nightly evaluator admits only approved
source refresh, measured-gap comparison, isolated read-only fixtures, reports,
bounded patch preparation, tests, and proposals. Arbitrary scraping, dependency
installation, access expansion, private mutation, task promotion, and merge are
denied as authority expansion.

## Closeout rules

A phase closes only when:

1. its required tasks and failure cases pass;
2. source and docs describe the same contract;
3. active plan checkboxes name the maturity achieved;
4. evidence is independent of the implementing agent's self-report;
5. root composition and operator path are tested where claimed;
6. stale/degraded/unavailable behavior is visible;
7. optional capabilities remain removable;
8. privacy/security review is current for newly introduced data classes;
9. all commands and artifact paths in the closeout are real;
10. the next unresolved phase remains active in `docs/plans/`.
