## Checklist and gate convention

- `[ ] ID — result to establish` means remaining work or acceptance, not proof that
  all supporting implementation is missing. Retained evidence is separate.
- `[x]` requires exact evidence or an explicit operator scope decision. State whether
  proof is source, fixture, installed, native or operator-accepted; never silently
  promote one class to another.
- Each implementation owner has a work checklist and observable exit gate, with
  prerequisites, verification and retirement rules. Product gates link their owner
  instead of duplicating implementation checklists.
- A missing credential, genuine input or operator verdict remains an open gate;
  agents do not fabricate it. Failures return to the narrow owning workstream.
- Close with evidence and retire the completed file; preserve history outside the
  active queue. Do not add compatibility stubs for every consolidated plan.
