# Arda Whole-System Completion Program

## Product outcome and current gate

Arda is the operator's coherent personal system across conversation, life, memory,
research, projects, models, devices and interfaces. It reduces remembering,
coordination, checking and recovery burden. Autonomous execution is one capability,
not a replacement for the [product doctrine](../architecture/ARDA_1_0_PERSONAL_AGENT_ECOSYSTEM.md).

Gate 1 in progress. M1 acceptance run `m1-gate1-execute-20260922` completed successfully — all 4 nodes (plan/approve/execute/verify) succeeded with passing test evidence. Source/package foundations and bounded installed execution/
restart receipts are substantial; the genuine connected operator scenario and
whole-system usefulness are not yet accepted. The September 15
reconciliation audit distinguishes
newer evidence from stale September 7 status and historical release claims.

This program owns product gates; the [portfolio](ARDA_PRODUCT_PLAN_SUITE.md) owns
navigation and the linked workstreams own implementation. Gates 1–5 express
execution/placement/project/improvement dependencies, not a universal serial queue.
Read-only personal/media/research work can proceed alongside runtime repair.
Gate 6 is not automatically earned by passing Gates 1–5.

## Canonical operating loop

Observe a genuine request or evidence-backed need → retrieve scoped context and
current project/source/receipt evidence → frame an outcome with acceptance,
authority, risk, budget and stop conditions → decompose dependency-aware work →
authorize → schedule through Engine → place admitted tools/workers through Manwë →
execute through Workbench/owning adapter → verify checks and visible artifacts →
independently review where required → close/revise/retry/defer or request one
concrete decision → record outcomes/corrections/learning with provenance.

Hermes owns conversation/workers; Engine ObjectiveStore owns objective/control/
schedule authority and RunStore evidence; Manwë owns routing; Vairë owns memory;
Oromë communicates; Aulë observes/executes its bounded adapter role; Rúmil/HADES
audits. Projections, timers and UI never become competing authority.

## Product gates

### Gate 1 — Complete the autonomous loop

- [ ] G1 — Pass the [single M1–M5 acceptance checklist](autonomous-task-completion/README.md):
  one genuine operator-authored multi-project objective enters through Hermes,
  survives scheduling, restart, failure, critic revision and cross-session continuation,

  operator reduced-burden acceptance.

qualification; minimal approved projects/providers may be implemented ahead of
Gates 2/3. Local fixture success cannot replace the genuine scenario.

### Gate 2 — Route real workers

- [ ] G2 — Pass [provider acceptance](PROVIDER_WORKER_CONVERGENCE.md#gate-2-acceptance-matrix):
  canonical work selects actual deterministic/local/hosted capacity by capability,
  tools, privacy, health, context and budget, with independent review and explicit
  authorized fallback or truthful refusal. Receipts show actual route and resources.

Exit: real canonical work consumes admitted capacity under policy; configured names
and optional paid-provider availability are not the gate.

### Gate 3 — Connect the project fabric

- [ ] G3 — Pass [fabric acceptance](CONNECTED_PROJECT_FABRIC.md#gate-3-acceptance):
  approved real project contracts or explicit exclusions, correctly rooted work,
  preserved dirty operator changes, meaningful metadata discovery and a verified
  correction of a real stale/incomplete claim.

Exit: production authority contains useful real bounded projects, not proof fixtures.
Reuse G1's cross-project receipt; do not create another copy of the scenario.

### Gate 4 — Activate daily improvement

- [ ] G4 — Pass the [seven-cycle window](DAILY_RESEARCH_IMPROVEMENT_LOOP.md#gate-4--seven-cycle-acceptance):

  idea, and provide a useful truthful brief accepted by the operator.

Exit: elapsed-use evidence of beneficial work and restraint. A timer, audit report,
review suggestion or rapid fixture loop is insufficient.

## Execution boundaries and retirement

- Do not replay accepted consequential actions to manufacture fresh receipts.
- Understand dirty-work ownership before mutation; discovery defaults to read-only.
- Credentials, external posts/purchases, destructive change and broad deployment
  retain explicit authority gates. A plan checklist is not blanket execution approval.
- Ambient Agent, Mirromere, RELIC expansion, sensors and physical outposts remain
  downstream of repeatedly useful accepted Core Arda. Retain their
  [deferred program](../archive/deferred/ambient-agent/README.md); no automatic promotion.

  only with dated scoped evidence, and move finished workstreams out of `docs/plans/`.
