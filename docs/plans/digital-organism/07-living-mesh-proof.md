# Stage 7 — Living Mesh Vertical Proof

## Objective

Prove the digital-organism architecture as one coherent, observable behavior rather than a collection of mature components.

## Required scenario

The operator submits a genuine bounded objective such as:

> Inspect one current project or system concern, gather evidence, obtain an independent critique, synthesize a recommendation, verify it against the source, and preserve enough context for another node to continue.

The objective must require at least three heterogeneous roles and at least two independently running node/process boundaries. A third role may begin simulated only if the plan records that limitation; final acceptance requires three independently running role executions.

## Acceptance flow

1. Hermes accepts the operator’s objective and resolves authenticated Arda context.
2. Arandur recovers the current objective and proposes the smallest role composition.
3. Governance classifies the work and exposes any required review.
4. Node registry and Manwë place roles using live capability/resource evidence.
5. Work crosses at least one standard A2A boundary.
6. Varda preserves sources/provenance and contradiction evidence.
7. Vairë emits bounded continuation context and memory-use receipts.
8. One worker/node is deliberately stopped after producing partial evidence.
9. Homeostasis expires/reconciles it, preserves completed work, and reassigns only eligible steps.
10. A verifier checks the synthesized result against exact acceptance conditions.
11. Aulë/HUD shows the real topology, roles, handoffs, pressure, failure, reassignment, and receipt lineage.
12. The same objective/context is reopened after Arda and Hermes gateway restart.
13. The operator assesses usefulness, coherence, explainability, and whether the system felt like one organism.

## Evidence package

Create one run directory containing versioned contracts, node manifests/observations, context capsule digests, A2A task/result IDs, placement and handoff receipts, failure/recovery events, evidence references, memory-use records, final outcome, and redacted operator verdict. Raw secrets, unrelated personal memory, and hidden reasoning are excluded.

## Failure criteria

The proof fails if:

- roles are manually copied between nodes;
- topology is decorative or fixture-only without labeling;
- an offline node remains healthy;
- a process-local child is described as durable;
- work repeats without reconciliation;
- a model/council output becomes approval;
- restart loses the objective or lineage;
- the UI disagrees with the canonical receipts;
- the operator must inspect internal JSON files to understand or continue the run.

## Exit gate

The operator explicitly accepts the run as a coherent digital-organism behavior. Engineering evidence alone cannot close this stage. Repeated use is required before downstream embodiment work becomes active.
