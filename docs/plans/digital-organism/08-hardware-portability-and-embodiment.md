# Stage 8 — Hardware Portability and Embodiment

## Objective

Demonstrate that the organism improves when transferred to stronger or specialized hardware because node identity, capability, placement, context, and receipt contracts are portable—not because workflows are rewritten for each machine.

## Boundary

This stage proves software/hardware portability and read-only embodiment first. It does not authorize custom PCB fabrication, actuators, sensors, account creation, payments, or public deployment. Those remain separately reviewed projects after the living mesh is repeatedly useful.

## Work packets

### S8.1 — Define portable node enrollment

A new node provides one declarative manifest plus attested observations for architecture, accelerators, memory, storage, network, power/thermal visibility, supported runtimes, transports, and privacy/physical capabilities. Paths and endpoints are deployment configuration, not contract identity.

### S8.2 — Validate heterogeneous placement

Run the Stage 7 capability request before and after enrolling a stronger or differently specialized node. Require a source-backed placement change where beneficial and no semantic change to objective, authority, context, or receipts.

### S8.3 — Integrate physical-state truth

Project real temperature, power, resource pressure, connectivity, and process health when available. Unavailable sensor data remains unavailable. No model may fabricate board or environmental state.

### S8.4 — Prepare embodiment interfaces

Mirromere/RELIC/pyramid/projector concepts consume the same runtime-presence and organism-outcome contracts. Begin read-only. Rendering, sensing, and eventual device execution stay separate capabilities with physical privacy controls and exact approval.

## Hardware evolution path

1. multiple processes on one host;
2. commodity LAN/Tailscale nodes;
3. constrained Pi/edge and stronger GPU nodes;
4. modular compute/sensor/display boards using proven standard links;
5. custom backplane/PCB/interconnect research only after traffic, power, thermal, serviceability, and failure semantics are measured;
6. physical shell/projector as expression of source-backed organism state.

## Exit gate

A newly enrolled stronger/specialized node changes real placement and improves a measured outcome without workflow code changes. The organism remains coherent when that node is removed. A read-only physical/native projection reflects genuine topology and activity with freshness and receipt lineage.
